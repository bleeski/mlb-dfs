# 2026-10-07 DEV (Session 134, R465(a)): the sliced door still serves the union, a filter is a separate row, and its hazards and cost are measured here

**Observed.** R465(a) shipped the facts: each conditions bucket's inputs are persisted beside `conditions_index`, and the brief names what a served bucket was built under (`anti_correlation.unrequested_built_under`) and fires `disagreement` when a known bucket differs from the build-level request in k, `target` or the leverage keys. `BankCache.as_candidates` still serves the UNION of every live bucket, so a k=0 build on a cache holding a k=2 bucket can seat those lineups; the brief now says so by name. The register's second half, "decide whether the sliced build door filters its served set to the buckets it requested", was decided NO for this session. The decision rests on hazards, not on cost.

**Hazards a filter must clear (each read in the tree at ebf9333).**
1. `_requested_sigs` (`build_slate.py`, in `run_classic` after the sleeves) is not complete for every family. A sleeve that finds the bank already holding enough (`already_held`, `execution_pipeline.py` build_sleeve_jobs, the tail, named-stack and environment branches) never calls `extend_bank`, reports no signature, and its earlier bucket is counted as unrequested on the repeat build. The R469 pair slice is NOT its own bucket (its pins live in the job key, so it shares the ordinary signature; the comment at `build_slate.py:4307` says otherwise). The salary-only sleeve's candidates live in a SIBLING file (`<stem>_salary_only.json`) that `count_outside_buckets` never inspects.
2. The four depth counters (tail, named stack, environment, pair) and the consensus-cluster source (`cache.as_candidates(None)`, `build_slate.py` and `execution_pipeline.py`) read the UNION. Filtering the served set alone makes a sleeve skip as "already held" over lineups the filter removed.
3. The bank-thin gate (exit 10, `bank_thin_partial`) counts the served candidates and the distinct SP pairs among them, so a filter can thin a bank that passes today. A legal file before the deadline outranks a cleaner served set; the repair is a top-up that serves unrequested buckets once the requested ones are thin, counted and named, which is a relax-and-count control with its own wording and its own test.
4. A filter changes which lineups the allocator may seat on every shared cache: a strategy-adjacent behaviour, not a labelling change.
5. Late swap shares the cache file and does not forward k (`tools/late_swap.py`, around `extend_bank(cache, projections, ...)`), and the 2026-10-06 fragment `late-swap-bank-cache-purges-the-builds-stored-jobs.md` reports its first slice retires the build's buckets; any filter is the sliced BUILD door's alone.
