# 2026-10-13 BUILD (2000_2g, Tue-Wed LCS draftgroup): a two-date draftgroup takes its slate date from the first salary row, not the first lock

**Observed.** DK's Tue-Wed draftgroup held CLE@TB (10/13 8:00 PM ET, ALCS G2) and MIL@LAD (10/14 8:00 PM ET, NLCS G3). The salary file's first row is Jacob Misiorowski, $10,500, a MIL@LAD row, because DK sorts by salary. `slate_date_from_salary` (`skills/generate-lineups/scripts/build_slate.py:2077`) returns the date of the first row it can parse, so `args.date` became `2026-10-14`. The brief carried `date: 2026-10-14` beside `slate.first_lock_local: 2026-10-13T20:00:00-04:00`, and every artifact landed under `outputs/2026-10-14/` and `data/slates/2026-10-14/`. Delivery records split across both dates: the attempt-1 refusal under `data/deliveries/2026-10-13/`, the baseline and the certified delivery under `2026-10-14/`. `tools/ownership_pred.py emit` printed `2026-10-14 2000_2g` from the same file.

**What it reached, and what it did not.**
- `slate_clock` was right: `first_lock_game_id CLE@TB`, `first_lock_utc 2026-10-14T00:00:00Z`. So was the preflight (`first lock: 2026-10-13 20:00 ET`).
- `rotowire_window(args.date, ...)` fetched the TOMORROW page, which carried only MIL@LAD. Here that was the right page by luck: MIL and LAD were the TBD sides and CLE/TB were posted. If tonight's game had been the TBD one, the merge would have read the wrong day and left those sides on the FanGraphs reference (14.9 days old on this build).
- `pool_report.platoon_age_days` read `-1` (`input_confidence.facts.stale_platoon_reference.value.age_days: -1`): the RotoWire block is stamped `collected_date: args.date` (10-14), and the pool aged it against a slate date of 10-13. A negative age clears R27's check by construction.
- Not reproduced, read from SKILL.md's R460 text only: a bare `--deliver-by HH:MM` "sits on the slate's own date, read off the salary file", so `--deliver-by 19:55` would have resolved to 10/14 19:55 ET, 24 hours past the real deadline. This build passed an ISO timestamp, so the governor saw `deliver_by_utc 2026-10-13T23:55:00Z`.

**A second gap on the same file.** `tools/preflight_upload.py` printed `WARN no lineups feed resolved; the posted-lineup cross-check did not run ... skipped: the file spans 2 slate dates ['2026-10-13', '2026-10-14']`. It is named, not silent, but the check that catches a benched starter skipped tonight's posted game entirely. I checked the 12 CLE/TB hitters against DK's `Starting` 1-9 by hand.

**Candidate item.** `slate_date_from_salary` returns the earliest game date across all rows (or the ET date of the first lock, which `slate_clock` already computes), so every reader of `args.date` agrees with the clock. Then re-check the readers named above: the RotoWire window (a two-date slate may need both pages), the platoon age, the bare `--deliver-by`, and the preflight's two-date skip, which could cross-check the sides that are posted and name the rest. Test: the vendored archive salary file with one high-salary row moved to the next day. Effort S for the date; the preflight half is its own decision.

Nothing here is a lift, an edge, an ROI or a win rate.
