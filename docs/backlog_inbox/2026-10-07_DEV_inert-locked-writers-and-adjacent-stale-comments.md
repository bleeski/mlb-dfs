# 2026-10-07 DEV (Session 134, R455(b) and R465(a)): the two kept `Locked` writers, and four comments read along the way that no longer say what the code does

**The kept `Locked` writers (R455(b)).** Session 134 dropped `Locked` from the projection contract (`CORE_PROJECTION_FIELDS`, `MLB_Classic.md`, `docs/MLB_Classic_Integration_Contract.md`) because a frame-level lock cannot be made honest against the exposure caps inside that row (a locked player is in every bank candidate, the allocator's R311 check then needs `max_player_exposure_pct` at 1.0 for everyone, and no per-player exemption exists). The two default writers were KEPT, deliberately: `projection_builder.py` (`CORE_COLUMNS`, which orders the builder's output, and the `if "Locked" not in frame.columns: frame["Locked"] = False` default) and `slate_intake_manager.py` (`"Locked": False`). Removing them changes the frame's columns, and `bank_cache.projection_digest` / `conditions_signature` hash EVERY column (`_projection_bytes`), so removal re-keys every conditions bucket and retires every cache on disk, and moves every run's `projections.csv` bytes. That is a one-time cache invalidation and a frame-schema change, and it belongs with the next one that has a reason to re-key. `LockedColumnTests.test_no_production_writer_sets_locked_true` pins exactly these two writers, both False, so a third writer or a truthy value fails a test. **Candidate item:** remove the two writers and `Locked` from `CORE_COLUMNS` in the same commit as the next intended frame-schema change; the tests' `"Locked": False` fixture cells then become inert extras and may stay. XS once there is a reason to re-key.
